## 2. Step-by-Step Player Workflow

1. **Pressing Capture Key**: The player hits `F2` or `Ctrl + F2`.
2. **Safety Check**: If a capture is already in progress or occurred within 300 ms, the request is safely debounced.
3. **GPU Texture Query**: The mod checks the GPU's maximum hardware texture boundary (`GL_MAX_TEXTURE_SIZE`). If exceeded, it automatically clamps dimensions proportionally and alerts the player in chat.
4. **Frame Rendering**: The game renders the frame into the designated render target.
5. **Zero-Lag Transfer**: The raw pixel bytes are transferred from the GPU into a RAM buffer (`NativeImage`), freeing the render thread immediately.
6. **Background Compression**: `Util.ioPool()` encodes the PNG and saves it to `.minecraft/screenshots/` on a background thread.
7. **Notification**: A chat message appears with a clickable file link to open the saved screenshot directly in the OS file explorer.

## 3. Mathematical Foundations & Formulas

### RAM Allocation Formula
The RAM required for the raw uncompressed pixel buffer is proportional to total pixels multiplied by 4 bytes (RGBA8):
$$\text{RAM}_{\text{bytes}} = W \times H \times 4 = W_{\text{base}} \times H_{\text{base}} \times S^2 \times 4$$
Where $S$ is the resolution scaling factor.

### Proportional UI Scaling
To ensure hotbars, crosshairs, and text remain legible rather than shrinking to microscopic dots at 4K or 16K, the target GUI scale is scaled proportionally:
$$\text{TargetGuiScale} = \max\left(1, \text{round}\left(\text{OriginalGuiScale} \times \frac{W_{\text{target}}}{W_{\text{original}}}\right)\right)$$

### Aspect-Preserving Hardware Clamp
If either dimension exceeds $M = \text{GL\_MAX\_TEXTURE\_SIZE}$, the dimensions are clamped while strictly maintaining aspect ratio $R$:
$$W_{\text{clamped}} = \min(W, M), \quad H_{\text{clamped}} = \text{round}\left(\frac{W_{\text{clamped}}}{R}\right)$$
$$H_{\text{clamped}} = \min(H_{\text{clamped}}, M), \quad W_{\text{clamped}} = \text{round}(H_{\text{clamped}} \times R)$$

## 6. Anti-OOM Guard & Hardware Safety

1. **Zero Render Stutter**: Because PNG writing happens asynchronously in `Util.ioPool()`, massive 16K screenshots do not freeze the Minecraft render thread.
2. **Auto-Disposal**: `OffscreenFramebuffer.dispose()` frees allocated buffers when switching dimensions to prevent GPU memory leaks.
3. **Debounce Protection**: A 300 ms threshold ensures rapid F2 spamming cannot exhaust JVM off-heap memory.

## 7. Developer Reference Snippets

### Hardware Clamp Implementation
```java
// net.vanillaoutsider.hyperscreenshots.render.HyperCaptureManager
public static ResolutionPreset.ResolutionDimensions clampToHardwareBounds(
        ResolutionPreset.ResolutionDimensions dimensions,
        int maxTextureSize,
        HyperScreenshotsConfig config,
        Minecraft minecraft) {
    if (dimensions.width() <= maxTextureSize && dimensions.height() <= maxTextureSize) {
        return dimensions;
    }
    double aspectRatio = (double) dimensions.width() / (double) dimensions.height();
    int clampedW = Math.min(dimensions.width(), maxTextureSize);
    int clampedH = (int) Math.round(clampedW / aspectRatio);
    if (clampedH > maxTextureSize) {
        clampedH = maxTextureSize;
        clampedW = (int) Math.round(clampedH * aspectRatio);
    }
    return new ResolutionPreset.ResolutionDimensions(Math.max(128, clampedW), Math.max(128, clampedH));
}
```
